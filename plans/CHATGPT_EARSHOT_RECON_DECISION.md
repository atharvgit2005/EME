EME × Earshot — Architecture Lead Review

Decision: APPROVED TO PROCEED TO IMPLEMENTATION PLANNING. The proposed read-only adapter is the right first integration boundary, with several requirements that must be resolved in the implementation plan before any source changes are authorized.

The central architectural decision is sound: Earshot should provide additional evidence about rendered audio, while EME retains exclusive control of planning, project mutation, repair execution, and delivery certification.

Your reconnaissance also identifies a high-value gap: static beat-marker checks cannot establish that actual audio transients align with rendered visual cuts. Earshot's waveform-based analysis can address that gap without giving the external service mutation authority.

This approval is not authorization to begin source edits yet. The reconnaissance was required to remain read-only, and that boundary remains in effect until the implementation plan is approved.

1. Architecture verdict

The proposed EarshotQaAdapter is approved as the preferred integration direction. The initial implementation should remain measurement-only, optional, bounded, and unable to mutate EME state.

The main architectural benefit is not replacing FFmpeg QA. It is adding three capabilities around the existing checks:

More rigorous loudness and true-peak measurements.

Direct analysis of sound onsets relative to the rendered picture's cuts.

Human-reviewable diagnostic sheets that connect the measurements to visual events.

Earshot's creative scorecard should remain advisory. A subjective “launch-grade” score must never override a failed technical-integrity check, a media decode failure, or EME's delivery-promotion requirements.

2. Required changes to the proposed design

A. Preserve a strict read-only boundary

Earshot returns observations only. It must not receive an operation executor, project-write API, session lease, fencing token, or delivery-promotion interface. Any later repair proposal must be generated by EME and passed through the existing planner and OperationExecutor.

B. Reconcile the timeout with cold-start behavior

The reconnaissance reports a 20–40 second model cold start but proposes a 15-second watchdog for full perception. Those are incompatible unless the worker is already warm. Define separate budgets for worker startup, model initialization, and each request. The first milestone should use fast, model-free measure and sfx check by default; full timeline perception should be opt-in or deferred until warmed-worker behavior is measured.

C. Keep canonical schemas untouched initially

The proposed request and response contracts should begin as internal versioned adapter contracts. Do not modify an existing canonical *.v1.schema.json schema. The canonical QA report should receive mapped results only through an explicitly reviewed, backwards-compatible integration point. Confirm that existing check IDs, severity enums, decision rules, and required report fields can represent the new findings before selecting the final mapping.

D. Normalize time carefully

Earshot's millisecond offsets must be converted into EME's integer tick representation using the project's canonical time utilities. The proposed offsetTicks: -18000 is correct for a 150 ms shift at 120,000 ticks per second, but a repair must also verify that the finding identifies the correct audio clip, accounts for render offsets and frame rate, and remains valid against the current project revision.

E. Treat subprocess output and diagnostic files as untrusted

Use bounded JSON lines, maximum response sizes, queue limits, watchdogs, process-tree termination, and sanitized child environments. Validate every response and resolved media/diagnostic path. A timeout, malformed response, missing Python environment, or Earshot crash must result in not_measured with native QA continuing—not a false pass or failure of the whole render.

4. Corrections to the certification test plan

Before implementation starts, resolve four details in the design.

True-peak ground truth. A signal measured at +2.2 dBTP and 120 clipped samples must be constructed and measured carefully. Once PCM samples are hard-clipped, the resulting waveform's true peak is not necessarily the originally intended +2.2 dBTP. The fixture generator must record both the pre-clipping intended signal and the final file's actual measured values.

Audio sync repair sign. Earshot defines offset as sound time minus picture time. Therefore, a +150 ms late impact corresponds to +18,000 ticks of observed offset at EME's timebase. The proposed shift is -18,000 ticks, but it must only be applied to the correct clip after confirming the rendered offset maps directly to that clip's timeline position.

LUFS threshold policy. The reconnaissance proposes a target band of -16 to -9 LUFS, a -1 dBTP ceiling, and a separate example targeting -14 LUFS. Treat these as configurable delivery profiles, not universal hard-coded requirements. The project must explicitly select the applicable profile.

Check status semantics. not_measured, not_applicable, warning, and failed must retain distinct meanings. Missing Earshot cannot count as a pass, and an unavailable optional check cannot automatically turn an otherwise valid render into a technical failure.
